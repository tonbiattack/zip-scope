# ZipScope MVP 仕様書 v0.1

## 目的
大量の未解凍ZIPを、展開済みフォルダと同じ感覚で閲覧するWindows専用ローカル画像ビューア。Pictobiやarchive-extract-cleanerとは独立させ、閲覧速度と操作数の少なさに特化する。

## 対象・非対象
Windows 11 x64。ローカルSSD/HDD・外付けドライブ上のZIP/CBZ（Store/Deflate、ZIP64）、JPEG/PNG/GIF（静止画）/WebP。ネット接続不要。RAR/7z、暗号化ZIP、入れ子ZIP、画像編集、移動・削除、クラウド同期はMVP外。元のZIPは読み取り専用。

## 技術構成
Go + Wails + Vue 3/TypeScript、archive/zip、SQLite（メタデータ）、ディスク上の縮小画像キャッシュ、仮想スクロール。依存バージョンは実装時に固定。画像配信はWailsのローカルアセットハンドラ等でIDから解決し、巨大なBase64 JSON転送を避ける。外部URLや任意のファイルパスを受け付けない。

## 画面・操作
- 起動時に前回のルートと選択位置を復元。フォルダ選択・ZIPのドラッグ&ドロップ。
- 左: ZIP一覧（代表画像、名前、画像枚数、サイズ、更新日時）。検索、名前自然順・更新降順・サイズ順。走査中も結果を逐次表示。
- 右: 選択ZIPのサムネイルグリッド。サイズ調節、ダークテーマ。選択で原寸ビューへ。
- 原寸ビュー: 画面フィット/等倍、ズーム、パン、左右キーで画像移動、Escで戻る。Ctrl+左右でZIP移動。選択位置・スクロール位置を復元。
- 代表画像は対応画像の自然順先頭。ディレクトリを含むパスを自然順で比較し同順位は元のエントリ順で安定化。画像なし・破損・非対応は状態表示。

## 読み込み・キャッシュ
1. ルートを非同期再帰走査し、シンボリックリンク/ジャンクションを追わない。アクセス拒否は記録して続行。キャンセル可能。
2. ZIP中央ディレクトリから画像候補を取得。全展開禁止。選択エントリだけストリーム展開し、画像ヘッダの寸法確認後にデコードする。ZIP内パスをディスク書き込み先に使用しない。
3. 可視領域・選択画像を最優先。前後2枚と隣接ZIP代表画像を低優先度で先読み。選択変更時は旧ジョブをキャンセルまたは結果破棄。重複ジョブを統合し並列度は初期4、HDDでは調整可。
4. SQLite: archives(path, size, mtime, fingerprint, status, count), entries(archive_id, ordinal, name, crc32, compressed_size, uncompressed_size), thumbnails(key, path, bytes, last_access)。キーはアーカイブ識別子＋エントリ識別子（ordinal/CRC/size）＋縮小サイズ＋生成バージョン。変更検知はサイズ/mtimeと中央ディレクトリ指紋を再オープン時に照合。キャッシュ書き込みは一時ファイルから原子的に置換。
5. キャッシュは%LOCALAPPDATA%/ZipScope配下。ディスク初期上限2GB、LRU削除、設定から変更/全消去可。メモリキャッシュ初期上限256MiB、デコード作業メモリも別途制限。ファイルハンドルを確実に閉じる。キャッシュ破損時は再生成。
6. 安全性: 展開サイズ上限（初期128MiB/画像）、画素数上限（初期40MP）、エントリ数上限（初期10万/ZIP）。実読み込みにも上限を課す。CRC不一致・暗号化・破損・切断は個別エラー。HTML/SVG等は表示しない。入力に応じて上限を見直すが無制限にはしない。

## 性能目標（未計測、MVP受入目標）
Windows 11 / SSD / 1000 ZIP・各100枚のJPEG（1枚1〜5MB）の合成データで測定。キャッシュ有無を分離、各操作30回のp50/p95、CPU/RAM/ディスクを記録。HDDでも別計測。
- キャッシュ済み初期一覧の最初の描画: p95 500ms以内
- キャッシュ済みサムネイルグリッド初期表示: p95 200ms以内
- 先読み済み画像切替: p95 100ms以内
- 未キャッシュ初回画像: SSDでp95 1秒以内を目標
- 1万ZIPでスクロールしても全件画像をデコードしない。走査・生成中もUI操作可能、メモリが件数比例で無制限に増えない。
達成できない場合は実測とボトルネックを記載し改善する。

## テスト・配布
Go単体テスト、競合検査、Vueコンポーネントテスト、Windows実機スモーク。日本語/Unicode名、重複名、ZIP64、空ZIP、破損、暗号化、巨大画像、外付けドライブ切断、キャッシュ失効、連打で旧画像が出ないこと、元ZIPが変更されないことを検証。合成画像でベンチを再現可能にする。GitHub Releases用Windows x64ビルドとREADME（操作・制約・キャッシュ場所）を用意する。

## MVP完了
フォルダ指定からZIP一覧→グリッド→画像閲覧がオフラインで完結し、再起動後もキャッシュが再利用される。例外時に操作継続でき、性能測定値と配布物が揃う。
