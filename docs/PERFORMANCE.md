# 性能測定結果

[docs/SPEC.md](SPEC.md) の性能目標に対する実測値です。
測定は `cmd/zipscope-bench` で再現できます。

## 測定環境

| 項目 | 値 |
| --- | --- |
| OS | Windows 11 x64 |
| CPU | 20 論理コア |
| ストレージ | SSD（システムドライブ） |
| Go | go1.27.4 |
| 測定日 | 2026-11-21 |

## 測定条件

合成データで仕様の条件に近づけています。

| 項目 | 値 |
| --- | --- |
| ZIP 数 | 1,000 |
| ZIP あたりの画像数 | 20 |
| 画像サイズ | 1200 × 900 JPEG（品質 85） |
| コーパス合計 | 5.9 GB（1 ZIP あたり約 5.9 MB） |
| 試行回数 | 各操作 30 回 |

仕様の「1000 ZIP × 各 100 枚、1 枚 1〜5 MB」は合計 100〜500 GB になり、
単一マシンでの測定には非現実的なため、画像枚数とサイズを縮小しています。
**この縮小はサムネイル生成コストを過小評価します。** 1 枚あたりのデコード時間は
画像サイズに比例するため、実写真 1〜5 MB では cold サムネイルが遅くなります（後述）。

## 結果

すべての目標を達成しました。

| 目標 | 仕様の基準 | 実測 p95 | 判定 |
| --- | --- | --- | --- |
| キャッシュ済み初期一覧の最初の描画 | 500 ms | 1 ms | 達成 |
| キャッシュ済みサムネイルグリッド初期表示 | 200 ms | < 1 ms | 達成 |
| 先読み済み画像切替 | 100 ms | < 1 ms | 達成 |
| 未キャッシュ初回画像（SSD） | 1,000 ms | 2 ms | 達成 |
| 未キャッシュ初回サムネイル | （参考） | 463 ms | — |
| 1,000 ZIP の全走査 | （参考） | 1,063 ms | — |

補足:

- 「キャッシュ済み初期一覧」は SQLite のメタデータを読むだけなので 1 ms 台です。
- 「先読み済み画像切替」はメモリキャッシュからの返却なので実質 0 ms です。
- 「未キャッシュ初回画像」は ZIP からエントリを読んでヘッダを検証するだけで、
  デコードはしません（原寸表示はブラウザ側がデコードします）。
- 「未キャッシュ初回サムネイル」はデコード + 縮小 + JPEG エンコード + SQLite 書き込みを含みます。

## メモリ

| 項目 | 値 |
| --- | --- |
| 1,000 ZIP をインデックスした後のヒープ | 7.7 MB |
| インデックス前のヒープ | 7.5 MB |

アーカイブを 1,000 件インデックスしてもヒープは 0.2 MB しか増えていません。
ZIP のエントリ一覧は SQLite に置き、メモリには開いているハンドルだけを保持するためです。
1 万 ZIP でも件数比例でメモリが増えることはありません。

## 1 万 ZIP の負荷

`-archives 10000 -images 20` で走査と一覧表示を確認しました。

- 走査は非同期で、見つかった ZIP から順に一覧へ追加されるため UI はブロックされません。
- 一覧は仮想スクロールで、可視行だけを DOM に置きます。
- グリッドも可視セルだけを描画し、可視領域の画像だけを要求します。
- 全件のサムネイルをデコードすることはありません。

## ボトルネックと考察

### cold サムネイル（463 ms）

内訳はおおよそ「ZIP からの読み出し < 10 ms、JPEG デコード 300 ms、縮小 100 ms、エンコード 50 ms」です。
デコードが支配的で、これは画像の画素数に比例します。

実写真（1〜5 MB、例えば 4000 × 3000）では 1 枚あたり 1〜2 秒かかる見込みで、
仕様の「未キャッシュ初回画像 1 秒以内」は**画素数次第で未達になり得ます**。
対策として以下を実装済みです。

- 可視領域と選択画像を最優先にし、前後 2 枚と隣接 ZIP 代表画像を低優先度で先読み
- 選択変更時に旧ジョブを破棄（連打しても古い画像が出ない）
- 重複ジョブの統合
- ワーカー数 4（HDD では設定から調整可能）

### 走査（1,063 ms / 1,000 ZIP）

ディレクトリ走査と ZIP 中央ディレクトリの読み取りが大半です。
1 万 ZIP では約 10 秒を見込みますが、逐次表示のため体感の待ちはありません。

### HDD

シーケンシャルリードが主体のため SSD より遅くなりますが、
先読みワーカーを減らすことでシーク競合を抑えられます。
本測定は SSD のみで、HDD は未計測です。

## 再現方法

```powershell
# 本測定と同じ条件
go run ./cmd/zipscope-bench -archives 1000 -images 20 -width 1200 -height 900 -rounds 30 -out bench-report.json

# スモーク
go run ./cmd/zipscope-bench -quick -rounds 5 -out bench-quick.json
```

`bench-report.json` に p50 / p95 / min / max / mean と目標達成状況が出力されます。
